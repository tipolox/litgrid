# LitGrid Community Edition v1.2.0 — proposed notes, not published

Version preparation remains **NO-GO** pending independent review, founder acceptance of a measured workload/performance budget and disposition of qualification caveats. See [integrated qualification](v1.2.0-qualification.md). All actual package versions remain 1.1.0.

## Proposed changes

- **Monetary column controls — #37 / PR #38.** Optional `GridColumn.sortable` and `filterable` flags control header-menu actions. Defaults preserve existing behavior. Decimal-string amounts remain exact strings; applications can delegate exact comparison to the server. UI opt-outs do not disable imperative or server-query APIs.
- **Stable row selection — #36 / PR #39.** Add `selection-change`, frozen selection snapshots, `selectRowByKey`, and optional `selection.rowKey` / `scopeKey` coordination across Web, React, Vue, Angular and Blazor. Valid unique keys preserve identity through replacement and sorting. Duplicate, missing and invalid keys are unselectable; scope changes clear selection. Selection is cleared when records leave the displayed filter/page rather than transferred to another record.
- **External query/pagination — #35 / PR #40.** Opt into `queryMode:'external'`, supply immutable atomic `externalState`, and handle query events/callbacks. Search/filter/sort/page/page-size/refresh share request identities; known/unknown totals and loading/error/empty/out-of-range states are supported. Processing is bounded by supplied page rows.
- **Keyed-index performance — PR #42.** Share validated source/display indexes when the original view is unchanged; reuse them after checking every identity; avoid unnecessary inactive-transform copies. Same-reference identity mutations still synchronize synchronously. Duplicate validation and first-interaction correctness are preserved; no scan is deferred to first click.
- **Qualification/quality infrastructure — PR #41.** Correct stale wrapper fixtures, add a bounded public API/adapter contract gate, and verify candidate checksums after release-artifact download. Broad root TypeScript under #31 remains failing; the scoped gate does not repair or replace it.

## Integration guidance

Upgrade all npm packages and Blazor NuGet/bundled JS together to a separately approved coordinated version. Review lockfiles and cached/static assets. An older first registration of `yc-grid` cannot be replaced by later loading a newer adapter.

Local/index selection remains the default. Stable keyed selection adds identity guarantees and cold initialization cost. React retains effect-triggered local-data synchronization, including in-place mutations; unchanged array identity does not bypass validation. Prefer small externally supplied pages when application workloads require tighter startup limits.

External mode uses immutable state replacement; legacy `data` is not the result input. Unknown totals expose `-1` through numeric getters. Preserve exact decimal strings in row values and server filter payloads. Applications own fetching, cancellation, authorization and stale-response guards. Guard both request identity and account/site epoch, including across unmount/remount. For scope switches, remount by scope or establish a greater controlled request ID after invalidation; `oldId + 1` can collide with the invalidation identity. `scopeKey` is not an authorization boundary.

Next.js should register/import the grid only on the client, for example `next/dynamic(...,{ssr:false})`. React's `data` prop remains required; pass `[]` with external state. Abort pending work and invalidate application guards on unmount.

## Measured limits and caveats to retain

- Current optimized 100k keyed adoption p50/p95 is **38.4/57.9 ms** at 120 columns and **37.7/66.2 ms** at 200 (`n=60` each). Historical v1.1.0's same configured workloads measure **11.3/25.4** and **12.6/24.6 ms**, but do not implement stable identity guarantees. The old 89–102 ms candidate p95 is pre-optimization history, not current main.
- Explicit unkeyed legacy controls show p95 changes from −1.9 to +2.5 ms in the tested workloads. This is not a universal equivalence or parity claim. Keyed cold construction still adds cost; revalidation remains O(n).
- 100k React update-plus-two-frame p95 is **34.5–34.6 ms** (`n=150/case`); render p95 is small. Cold first-click-through-Lit-update p95 is **11.7/13.2 ms** (`n=20`), excluding physical input hardware and compositor paint. No dataset-sized deferred first-click scan was observed.
- A proposed reference-fixture budget includes keyed cold p95 ≤35 ms at 30k and ≤75 ms at 100k, React update p95 ≤40 ms, first click through Lit update p95 ≤16.7 ms, and changing 20-row external commit p95 ≤5 ms. **These post-hoc thresholds are unapproved; fitting them is not a release-budget PASS.** The founder must separately accept workload scope and latency tradeoffs.
- Broad root TypeScript remains **EXISTING BLOCKERS** under #31. Raw diagnostics, same-environment comparisons and scoped/installed-package results remain visible.
- Chromium keyboard/DOM/ARIA/status checks do not establish spoken announcements or WCAG certification. **Actual screen-reader speech remains unverified.** Safari, physical touch, Blazor WASM and a matrix of all advertised Angular majors remain unverified.
- Refreshed target consumers are Next 16.4.2, React/React DOM 19.2.5, Vue 3.5.32, Angular 22.1.3 and net8.0 Blazor Server. Angular validation uses supported Node **22.22.3** with engine-strict installation, replacing the earlier unsupported Node 22.14 qualification condition. Local .NET SDK is 10.0.402; GitHub validation uses .NET 8 SDK.

No publication, release tag, deployment or Property Management change is authorized by these proposed notes.
