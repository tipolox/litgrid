# LitGrid Community Edition v1.2.0 — draft, not published

This proposed text is for a future reviewed CHANGELOG/release entry. Version preparation is currently NO-GO pending the qualification decision in [v1.2.0-qualification.md](v1.2.0-qualification.md).

## Proposed changes

- **Monetary column controls — #37 / PR #38.** Optional `GridColumn.sortable` and `filterable` flags control header-menu actions. Defaults preserve existing behavior. Decimal-string amounts remain exact strings; opting out of local UI actions lets applications delegate exact comparison to a server.
- **Stable selection — #36 / PR #39.** Add `selection-change`, selection snapshots, `selectRowByKey`, and optional `selection.rowKey` / `scopeKey` coordination across Web, React, Vue, Angular and Blazor. Valid unique keys preserve identity through row replacement and sorting; scope changes clear old selection. Invalid or duplicate keys are not safe selectable identities.
- **External queries and pagination — #35 / PR #40.** Opt into `config.queryMode:'external'`, provide an immutable atomic `externalState`, and handle `query-change` / adapter callbacks. Search/filter/sort/paging/refresh share request identities. Support known/unknown totals and explicit loading/error/empty/out-of-range states. Applications own fetching, cancellation, authorization and stale-response guards.
- Add a scoped public API/adapter contract typecheck and correct stale wrapper fixtures. This does not repair the broad root TypeScript baseline tracked by #31.

## Upgrade and integration notes

Upgrade all LitGrid npm packages and any Blazor NuGet/bundled JS used on the same page together to the approved coordinated version. Review lockfiles, rebuild consumers and update cached/static assets. An older `yc-grid` registration cannot be replaced by loading a newer adapter later.

Local mode remains the default. External mode requires immutable state replacement; legacy `data` is not the server result input. Unknown totals expose `-1` through existing numeric getters. Keep exact decimal strings in rows and server filter payloads; UI opt-outs do not disable programmatic APIs.

Next.js consumers should register/import the grid only on the client, for example a client component with `next/dynamic(..., {ssr:false})`. React's `data` prop remains required; use `[]` when supplying external state. Abort pending requests and clear application guards on unmount. Guard responses by both request ID and account/site epoch, including across remounts. For scope switches, either remount with a scoped key or establish a greater request ID after the configuration transition; `oldId + 1` can collide with the scope invalidation identity.

## Limits to retain in the approved notes

- Qualification reproduced a material startup cost for stable keyed local datasets. The release remains blocked until a mitigation or explicit workload budget is approved; do not remove this item without new evidence/approval.
- Root TypeScript still fails under #31. Passing package builds and the scoped contract gate are not a green root typecheck.
- Chromium keyboard and ARIA/status checks passed. Actual screen-reader speech, Safari, physical touch and Blazor WASM were not verified; no WCAG certification is claimed.
- Tested packed consumers: React/React DOM 19.2.5, Next 16.4.2, Vue 3.5.32, Angular 22.1.3, net8.0 Blazor Server on .NET 8.0.12. This does not establish every advertised Angular major. Use Node satisfying framework engine requirements.

No packages, release or deployment were published by qualification. Property Management is unchanged.
