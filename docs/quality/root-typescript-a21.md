Issue [#57](https://github.com/tipolox/litgrid/issues/57), parent [#27](https://github.com/tipolox/litgrid/issues/27). Baseline: latest main at `66a1d3982b1ec5b53dbab867fe754016ddc82cb3`, verified before edits in the dedicated `quality/root-typescript-a21` worktree.

## Reproduction and baseline

Use Node **22.22.3**, pnpm **10.33.0**, and lockfile TypeScript **6.0.3**, matching A2 and CI. Run `pnpm install --frozen-lockfile` and the documented `pnpm build` prerequisite before comparing the historical root diagnostic inventory. All eight package/application builds passed before editing.

The untouched post-build `node node_modules/typescript/bin/tsc --noEmit --pretty false` (equivalent to `pnpm exec tsc --noEmit --pretty false`) reproduced **52 diagnostics**, exactly matching issue #57:

| Cause | Codes | Count |
| --- | --- | --- |
| Legacy Node module resolution in dependency and generated declarations | TS2307 ×12, TS2882 ×2 | 14 |
| Strict tests and benchmarks | TS18048 ×6, TS2683 ×2, TS2345 ×6, TS2339 ×12, TS2790 ×1, TS2341 ×5 | 32 |
| Node tooling ambient type discovery | TS2591 ×6 | 6 |

Five resolution reports came from Angular's intermediate `dist/out-tsc` declarations, which cannot resolve package-local Lit dependencies from that output location. Nine came from dependency declarations using modern package exports that the legacy root resolver cannot resolve. These are distinct from the 32 legitimate fixture/benchmark errors.

## Project ownership and commands

`pnpm typecheck:all` is the repository TypeScript quality gate. It runs an ownership audit followed by two strict, no-emit compilations. It needs installed dependencies, **not a package build**. It uses the installed TypeScript API to expand each configuration and Git's tracked plus nonignored untracked inventory to reject authored TypeScript outside those projects. New source directories must acquire an explicit owner; new files under the existing globs are included automatically. Git is required. Ignored local caches and generated outputs are outside the authored inventory.

| Project | Owned files and purpose |
| --- | --- |
| `tsconfig.quality.browser.json` | All supported TypeScript extensions under `packages/*/src`, `packages/*/tests`, `apps/*/src`, and `tests`: production browser sources, all unit tests, benchmarks, playground sources, public API fixtures, browser integration fixtures, and React JSX declarations. Uses DOM libraries and Node ambient types for the Vitest/Vite harness. |
| `tsconfig.quality.tools.json` | TypeScript under `scripts` and `vitest.config.ts`. Explicit Node types and ES2022 libraries; Bundler resolution matches Vitest tests and Vite's bundled configuration loading. Overrides root's config-file exclusion. |
| Existing package build configs | Unchanged shipping compilation, declaration generation, and Angular template/compiler validation. |
| `tsconfig.contracts.json` and four Web Component test configs | Retained A2 strict source/public-contract and compatibility gates. These deliberately overlap the repository quality projects. |
| `tsconfig.published-contracts.json` | Retained build-dependent public export identity, negative historical-shape, and browser fixture validation against actual package declarations, including Angular's flattened shipping output. |

The audit accounts for **113 authored TypeScript files** and **29 historical generated declaration siblings**. A legacy declaration is recognized only under core/renderer/web package sources, when its tracked/nonignored TypeScript source and declaration map also exist. TypeScript prefers the same-basename implementation source; these old declarations are not an independent authored contract. Fresh declarations are regenerated by package builds and validated by A2's published gate. `dist`, package build outputs, and dependency declarations do not become unrelated root source files. No authored source is excluded to obtain a pass. The archived `docs/performance/evidence/keyed-selection/tsconfig.performance.json` is historical machine-specific evidence, not an active project and contains no additional authored TypeScript.

Root `tsconfig.json` remains the shared options base so existing package compilation and exports are preserved. The solution **replaces the broad root command as the quality gate**; it does not claim that bare root `tsc --noEmit` is green. That command still sweeps generated outputs with legacy resolution and implicit ambient type discovery. Use the project command for repository checking and the published gate after builds. Neither `strict` nor library checking is weakened.
